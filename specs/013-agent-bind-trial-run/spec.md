# Feature Specification: 前端 agent 绑定工作流与工作流试运行

**Feature Branch**: `013-agent-bind-trial-run`

**Created**: 2026-09-23

**Status**: Draft

**Input**: User description: "还缺少两个功能 1. 前端agent绑定workflowid 2. 前端和后端都支持单次运行测试， 3. 疑问，现在的chatworkflow时携带上下文历史的还是没有"（疑问 3 已于 2026-09-23 调查答复：chat workflow 不携带上下文历史——每轮独立单输入，spec 07 冻结决策 O3；用户拍板维持现状，本篇不改）

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 管理员为 agent 绑定 / 解绑对话型工作流 (Priority: P1)

管理员在 agent 创建 / 编辑表单里看到一个「绑定工作流」下拉：只列出对话型（chat 型）工作流与一个「不绑定」清空态。选中后保存，agent 与该工作流建立绑定；再次编辑时清空选择并保存即解除绑定。绑定后该 agent 的会话由工作流接管（既有后端行为，会话界面零改动）。表单对绑定项给出说明文字，让管理员知道「绑定后对话将直接由该工作流处理」。

**Why this priority**: agent↔workflow 绑定是后端早已交付（spec 05）却无法从界面使用的核心断头路；打通后「绑定工作流的智能体」这一产品形态才成立。

**Independent Test**: 创建一个 agent 并绑定某 chat 型工作流 → 保存成功、重新打开表单回显绑定；清空再保存 → 绑定解除。全程不触碰工作流页面。

**Acceptance Scenarios**:

1. **Given** 系统中存在 chat 型与 task 型工作流若干，**When** 管理员打开 agent 表单点开「绑定工作流」下拉，**Then** 只出现 chat 型工作流（名称可辨），task 型不出现；存在「不绑定」清空态。
2. **Given** 管理员选中一个 chat 型工作流并保存，**When** 重新打开该 agent 编辑表单，**Then** 下拉回显既有绑定。
3. **Given** 已绑定的 agent，**When** 管理员清空绑定并保存，**Then** 绑定解除（服务端按全量更新语义落空）。
4. **Given** 提交时所选工作流已被他人并发删除，**When** 保存，**Then** 错误提示（工作流不存在）可读，表单留页内容不丢。
5. **Given** 系统中没有任何 chat 型工作流，**When** 打开下拉，**Then** 空态提示引导先去创建工作流，不阻断表单其余字段提交（不绑定）。

### User Story 2 - 编排者从编辑页 / 详情页发起试运行 (Priority: P2)

编排者在工作流**编辑页**工具栏与**详情页**都能点「试运行」：弹出对话框，按工作流类型渲染入参表单，填好后执行；编辑页若有未保存改动，先提示保存（试运行执行的是已落库版本）。一次试运行 = 一次对当前已保存工作流的单次执行测试。

**Why this priority**: 发布前无法验证工作流行为是编排体验的最大缺口；后端单次执行能力（spec 06，含草稿态试运行）已交付，只缺界面入口。

**Independent Test**: 对一个已落库工作流（draft 或 published）点「试运行」→ 填入参 → 执行 → 看到结果。可在详情页独立完成，不依赖编辑页。

**Acceptance Scenarios**:

1. **Given** 详情页展示某工作流，**When** 点「试运行」，**Then** 对话框打开并按类型渲染入参表单。
2. **Given** 编辑页存在未保存改动，**When** 点「试运行」，**Then** 先提示保存（试运行跑的是已保存版本），不静默跑旧图。
3. **Given** 编辑页无未保存改动，**When** 点「试运行」，**Then** 直接打开对话框。
4. **Given** 对话框已打开且上一次结果在展示，**When** 修改入参再次点「执行」，**Then** 以最新入参重新执行，结果区刷新。
5. **Given** 两步式创建第二步（工作流尚未落库、没有 id），**When** 查看该页工具栏，**Then** 不出现「试运行」入口。

---

### User Story 3 - 试运行结果与错误可读呈现 (Priority: P3)

执行期间按钮 loading、不可重复触发；成功后展示最终输出文本与逐节点执行轨迹表（节点、类型、状态、耗时，按执行序排列）；失败时按统一错误信封给出可读文案（如工作流不存在 / 执行失败 / 环境限制类错误），不裸抛技术细节。

**Why this priority**: 结果呈现决定试运行是否真能用来定位问题——节点轨迹让「卡在哪一步」一目了然。

**Independent Test**: 构造一个含条件分支的工作流试运行两次（分别命中不同分支），核对输出与轨迹表差异。

**Acceptance Scenarios**:

1. **Given** 试运行执行中，**When** 观察对话框，**Then** 执行按钮 loading 且重复点击不产生第二次请求。
2. **Given** 执行成功，**When** 查看结果区，**Then** 最终输出文本与节点轨迹表（节点 / 类型 / 状态 / 耗时，执行序）均展示。
3. **Given** 执行失败（如图非法或环境限制），**When** 查看结果区，**Then** 错误文案可读（统一错误信封），无裸异常文本。
4. **Given** 同一工作流改入参再次执行命中不同分支，**When** 对比两次轨迹表，**Then** 节点序列差异可见（条件分支走向可验证）。

---

### Edge Cases

- 绑定下拉为空（无 chat 型工作流）→ 空态提示，不阻断表单其余字段（US1 场景 5）。
- 绑定目标被并发删除 → 保存报「工作流不存在」，留页不丢内容（US1 场景 4）。
- 编辑页试运行遇未保存改动 → 先提示保存，不静默跑旧版本（US2 场景 2）。
- 试运行执行中重复触发 → loading 防重复，无并发第二次请求（US3 场景 1）。
- chat 型入参为空 / 纯空白 → 前端必填拦截，不发请求。
- chat 型入参超长（> 16384 字符）→ 前端拦截提示，不发请求。
- task 型按 schema 渲染的必填字段缺失 → 前端拦截并定位到行，不发请求。
- task 型工作流未声明入参 schema → 退化为单文本框直传（不硬造字段行）。
- draft / disabled 状态工作流发起试运行 → 正常放行（试运行模式放开状态限制）；disabled 同样可试。
- 试运行失败（工作流不存在 / 未发布 / 执行失败 / 环境限制类）→ 统一错误信封文案可读（US3 场景 3）。
- agent 既有表单字段（名称 / 模型 / 系统提示词等）与校验 → 零回归；绑定项不改变既有字段必填性。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: agent 创建 / 编辑表单 MUST 提供「绑定工作流」下拉：仅列对话型（chat 型）工作流，含「不绑定」清空态；无可选项时空态提示，不阻断表单其余字段。
- **FR-002**: 保存语义 MUST 对齐后端契约：创建携带所选工作流标识（缺省 = 不绑定）；编辑走全量更新（清空选择 = 解绑）；重新打开表单 MUST 回显既有绑定。
- **FR-003**: 工作流编辑页与详情页 MUST 提供「试运行」入口并共用同一对话框；编辑页存在未保存改动时 MUST 先提示保存；两步式创建第二步 MUST NOT 出现该入口（工作流未落库）。
- **FR-004**: 试运行入参表单 MUST 按工作流类型渲染：chat 型 = 单文本框（必填、长度上限 16384）；task 型已声明入参 schema = 按 schema 字段行渲染（值组装为 JSON 对象文本作为输入，必填字段前端拦截）；task 型未声明 schema = 单文本框直传。
- **FR-005**: 试运行 MUST 调用既有单次执行能力并携带试运行标记（草稿 / 停用态放行）；执行中 MUST 呈现 loading 且不可重复触发。
- **FR-006**: 执行成功后 MUST 展示最终输出文本与节点轨迹表（节点、类型、状态、耗时，按执行序）。
- **FR-007**: 执行失败 MUST 按统一错误信封呈现可读文案，不向前端界面裸抛技术细节。
- **FR-008**: 既有行为 MUST 零回归：agent 表单既有字段与校验、工作流列表 / 两步式创建 / 编辑 / 详情 / 双模式编辑器行为不变。

### Key Entities *(include if feature involves data)*

- **Agent 工作流绑定**: agent 对一个对话型工作流的可空引用；清空即解除；绑定后该 agent 会话由工作流接管（既有后端语义）。
- **试运行**: 对已落库工作流的一次单次执行测试：单条输入（按类型为消息文本或按入参 schema 组装的对象文本）→ 最终输出 + 逐节点轨迹；与真实流量可区分（后端既有语义）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 管理员全程经界面完成 agent 绑定 / 回显 / 解绑各一次（不借助接口工具），单次操作 ≤ 1 分钟。
- **SC-002**: 编排者对草稿态工作流在界面完成一次试运行并看到输出与节点轨迹，全程无接口工具。
- **SC-003**: 请求载荷对齐既有后端契约（Network 面板逐键核对：绑定字段可空携带、执行请求体为单一输入字段、查询串携带试运行标记）。
- **SC-004**: 既有页面人工回归零变化（agent 表单既有字段、工作流全线页面按既有用例复测通过）。
- **SC-005**: 前端构建门禁全绿：`cd web && npm run type-check && npm run build` 零错误。

## Assumptions

- 后端契约已交付且冻结（spec 05 agent 绑定、spec 06 单次执行与试运行、spec 07 会话管道），本篇后端零改动。
- chat workflow 会话不携带上下文历史（每轮独立单输入，spec 07 冻结决策 O3）——用户 2026-09-23 拍板维持现状。
- 绑定下拉仅列 chat 型为前端过滤（用户 2026-09-23 拍板）：chat 型输入为纯文本消息语义匹配；task 型入参为 JSON 对象文本，与聊天纯文本不匹配，故不做绑定入口。
- 工作流列表响应含类型字段、详情响应含入参 schema——既有能力，直接作下拉与字段行的数据源，无新接口。
- 会话界面零改动：绑定 workflow 的 agent 回复已能按既有会话 UI 渲染。
- 运行历史列表 / 运行详情页不在本篇（查询接口未暴露；节点轨迹即同步结果）。
