# Quickstart: 验证指南（前端 agent 绑定工作流与工作流试运行）

**Feature**: [spec.md](spec.md) | **Date**: 2026-09-23

本篇实现完成的定义 = 双门禁全绿；下列场景为人工验收路径（正式用例落 `docs/testing/agent-manual-test.md` / `docs/testing/workflow-frontend-manual-test.md` 增补小节，验收报告单列人工项清单）。

## 前置

```bash
# 后端 + 前端起本地环境（既有 make dev 路径）
make start ENV=dev

# 门禁（实现完成的硬判据）
cd web && npm run type-check && npm run build   # 预期：零错误退出
```

数据准备：≥1 个 chat 型工作流、≥1 个 task 型工作流（含 input_schema 字段，如 `q: string required`）、≥1 个 agent；task 型最好含条件分支（验证 SC 分支走向）。

## 场景 1 — agent 绑定 / 回显 / 解绑（US1，SC-001）

1. Agent 管理 → 创建 Agent → 「绑定工作流」下拉：**只出现 chat 型**（task 型不出现）；不选也能提交（其余字段校验不变）。
2. 选中一个 chat 型工作流 → 保存 → 重新打开编辑表单 → 下拉**回显**该绑定。
3. 清空下拉（×）→ 保存 → 重新打开 → 无绑定（PUT 解绑）。
4. Network 面板核对载荷（SC-003）：创建 / 编辑请求体含 `workflow_id: <数值>`；解绑提交该键**缺省**；响应 `workflow_id` 为字符串或 null。
5. 并发删除验证（可选）：开两个标签页，A 页选中工作流 W，B 页删除 W，A 页保存 → toast「工作流不存在」类文案，弹窗不关、内容不丢。

## 场景 2 — 详情页试运行（US2 / US3，SC-002）

1. 工作流详情页 → PageHeader 出现「试运行」按钮 → 点击 → 对话框按类型渲染：
   - chat 型：单文本框（placeholder 模拟用户消息，字数计数）；
   - task 型有 schema：字段行（必填带 `*`，缺失提交 → 定位到行、不发请求）；
   - task 型无 schema：单文本框直传。
2. 填参 → 执行 → 按钮 loading、期间重复点击无第二发请求（Network 只一条 POST）。
3. 成功：输出文本 + 轨迹表（节点 / 类型 / 状态 / 耗时，执行序）+ 总耗时。
4. 改参再执行（不关对话框）：结果区刷新为新结果；task 型条件分支改入参命中另一分支 → 两次轨迹表节点序列**可见差异**。
5. Network 核对：`POST /api/v1/workflows/{id}/execute?trial=true`，body 仅 `{"input": "..."}`；task 字段行时 input 为 JSON 对象文本（如 `{"q":"..."}`）。
6. draft 态工作流同样可试（trial 放开状态机）；构造失败工作流（如断开的图）→ 结果区 el-alert 可读文案 + 轨迹中断点可见，无裸异常文本。

## 场景 3 — 编辑页试运行（US2 场景 2/3/5）

1. 编辑页无改动 → 工具栏「试运行」→ 直接开对话框。
2. 画布上拖一个节点（制造脏态）→ 点「试运行」→ 弹「当前有未保存改动…」确认框；「去保存」→ 走既有保存链路；「取消」→ 留页、对话框不开。
3. 两步式创建第二步 → 工具栏**无**「试运行」入口。

## 场景 4 — 既有回归（SC-004）

按 `docs/testing/` 对应文档复测：agent 表单既有字段与校验（名称 / 模型必填、温度、上下文轮数、KB 绑定、RAG 参数）；workflow 列表 / 两步式创建 / 编辑（含脏态离开确认）/ 详情 / 双模式编辑器——行为零变化。
