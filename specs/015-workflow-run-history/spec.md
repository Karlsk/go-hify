# Feature Specification: workflow 运行历史与节点轨迹查询

**Feature Branch**: `015-workflow-run-history`

**Created**: 2026-09-24

**Status**: Draft

**Input**: User description: "在 workflow 的页面，某个 workflow 的详情页可以看到调用的记录和每次调用时经过哪些 node、每个 node 的运行状态、输入输出"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 运行历史列表（Priority: P1）

编排者在 workflow 详情页新增的「运行历史」区块看到该工作流的全部调用记录：每条含状态（成功/失败）、触发来源（控制台试运行 / 对话触发 / 子工作流嵌套）、是否试运行、耗时、失败节点、错误摘要、调用时间与运行编号；列表最新在前，翻页加载更多。

**Why this priority**: 查询入口是本篇价值根基——没有列表就无法定位"第 N 次调用"；仅列表本身（不含详情下钻）已可满足"看调用记录与成败"的最低需求。

**Independent Test**: 对一个执行过若干次（含成功与失败）的工作流打开详情页，运行历史列表出现全部记录、摘要字段齐全、翻页正确；纯后端可用列表查询接口直接验证。

**Acceptance Scenarios**:

1. **Given** 工作流已执行过 25 次，**When** 打开其详情页运行历史区块，**Then** 列表展示最新 20 条（最新在前），提供加载更多入口，剩余 5 条可翻出且无重复无遗漏
2. **Given** 工作流有失败调用，**When** 查看列表，**Then** 失败行状态标红、失败节点与错误摘要可直接读到
3. **Given** 工作流从未执行过，**When** 打开运行历史区块，**Then** 展示空态说明（非错误、非空白崩溃）

---

### User Story 2 - 运行详情与节点轨迹（Priority: P2）

在运行历史列表点击某条记录，打开该次运行的详情视图：运行级输入、输出、错误文案、失败节点、触发来源、开始与完成时间、父子运行关联、总耗时；以及按执行序排列的节点轨迹表——每个经过的节点一行，含节点 key、类型、运行状态、耗时、输入、输出；失败运行的失败节点行高亮定位。

**Why this priority**: "每次调用经过哪些 node、每个 node 的运行状态、输入输出"是需求原文的核心；依赖 US1 的列表作为入口，故列 P2。

**Independent Test**: 一次含失败节点的执行后，从列表点开该运行，节点轨迹与执行时实际路径一致（节点集合、顺序、各节点成败与输入输出），失败节点高亮且错误文案可读；纯后端可用运行详情查询接口验证。

**Acceptance Scenarios**:

1. **Given** 一次成功执行经过了 A→B→C 三节点，**When** 打开其运行详情，**Then** 节点轨迹表按执行序恰好三行，各节点状态成功、输入输出可读，运行级输出与最终输出一致
2. **Given** 一次在 B 节点失败的执行，**When** 打开其运行详情，**Then** 轨迹表 B 行高亮（失败），运行级错误文案可读且指向 B；A 行为成功、C 行不存在（失败后未执行）
3. **Given** 输入或输出内容过长被落库截断的运行，**When** 打开详情，**Then** 如实展示截断后的文本（含截断标记），不报错不空白

---

### User Story 3 - 试运行联动与数据窗口（Priority: P3）

刚在详情页试运行完的调用立即出现在运行历史顶部，关闭试运行对话框后仍可再次点开核对完整输入输出与轨迹；运行历史是有限窗口——超过保留期的旧记录会被清理，列表变短或为空属正常态。

**Why this priority**: 闭环体验与预期管理，依赖 US1/US2 已交付，单独价值低故列 P3。

**Independent Test**: 试运行一次（成功或失败）后刷新/查看运行历史列表，顶部出现该次记录且 is_trial 标识为试运行，点开详情数据与试运行结果一致。

**Acceptance Scenarios**:

1. **Given** 详情页试运行刚完成，**When** 查看运行历史，**Then** 顶部出现该次记录、标注为试运行，点开详情与试运行当次结果一致
2. **Given** 一个只 retained 近期记录的环境（旧记录已被保留期清理），**When** 翻运行历史，**Then** 只见近期记录或空态，无错误提示

### Edge Cases

- 运行 id 不存在、或存在于其他工作流下：详情查询返回 404 与错误码 `RUN_NOT_FOUND`，不泄露其他工作流的存在性
- 分页游标被篡改或非法：返回 400 校验类错误（游标对前端不透明、原样回传是唯一合法用法）
- 每页条数传 0、负数、非数字或超过上限：按上限封顶 / 默认值归一，不报错不失控
- 对话触发的运行（关联会话与消息）：照常出现在列表，触发来源显示为对话；会话/消息关联字段在详情可读
- 子工作流嵌套产生的运行：作为子工作流自身的运行记录出现在子工作流的历史里，详情透出父运行编号；父运行详情不反查子运行列表
- 节点轨迹为空的运行（防御路径）：详情正常打开，轨迹区展示空态而非报错
- 保留期内但落库失败的运行（执行引擎既有的降级路径）：该次执行不出现在历史中，历史查询行为不受影响

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供按工作流查询运行历史的接口：以游标方式分页（默认每页 20、上限 100、最新在前），每条记录返回摘要字段——运行编号、状态、触发来源、是否试运行、耗时、失败节点、错误信息、调用时间
- **FR-002**: 运行历史列表的每条记录 MUST NOT 携带输入与输出大文本（大文本仅在单次运行详情中返回）
- **FR-003**: 系统 MUST 提供单次运行详情查询：按工作流与运行编号返回运行全字段（输入、输出、错误信息、失败节点、触发来源、是否试运行、会话/消息关联、父运行编号、执行开始时间、记录时间、总耗时）与该运行的节点轨迹列表（按执行序：节点 key、类型、状态、耗时、输入、输出）
- **FR-004**: 运行不存在或不属于所查工作流时，详情查询 MUST 返回 404 与错误码 `RUN_NOT_FOUND`（本篇新增的唯一错误码）
- **FR-005**: workflow 详情页 MUST 新增「运行历史」区块：列表分页加载（最新在前），点击记录打开运行详情视图（运行级信息与输出 + 节点轨迹表，失败节点高亮）
- **FR-006**: 详情页既有区块（基础信息、Schema、图编排、试运行入口）MUST 零变化（新增区块不触碰既有结构）
- **FR-007**: 运行历史全链路 MUST 为只读：不提供对运行记录的修改、删除、重试或取消操作
- **FR-008**: 既有 workflow 接口、执行引擎与落库行为 MUST 零变化（本篇为纯查询加法）

### Key Entities *(include if feature involves data)*

- **运行记录（WorkflowRun）**: 一次工作流调用的完整存档（前序篇已交付的实体，本篇只读暴露）。关键属性：状态（succeeded / failed 两终态，无进行中态）、触发来源（console / chat / workflow）、是否试运行、输入与输出（落库时截断保真）、错误信息与失败节点、总耗时、执行开始时间、记录落库时间、父运行关联、会话/消息关联、链路追踪标识
- **节点轨迹记录（WorkflowNodeRun）**: 一次运行内按执行序排列的节点步骤。关键属性：所属运行、执行序号、节点 key 与类型、状态、输入与输出摘要、耗时

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 编排者在 workflow 详情页内即可完成"找某次调用 → 看节点轨迹 → 定位失败节点与错误"全流程，无需查数据库或服务器日志
- **SC-002**: 运行历史翻页在任意深度无重复、无遗漏记录（游标语义，逐页可核对）
- **SC-003**: 运行历史列表响应轻量（单条记录不含大文本），翻页加载速度不随记录内容体积变化
- **SC-004**: 后端全量测试绿 + workflow 模块覆盖率维持 ≥80% + 前端双门禁（类型检查与构建）零报错
- **SC-005**: 存量回归零变化：既有 8 个 workflow 端点行为、执行落库链路、试运行对话框、详情页既有区块全部保持原状（自动化回归 + 人工复测）

## Assumptions

- 运行两表与落库链路已由前序篇交付（迁移 00019/00020 已 applied），本篇零迁移、零执行引擎改动
- 运行记录不做用户维度隔离（一期业务接口不按用户隔离的既有约定），任何登录用户可查任何工作流的运行历史
- 列表"最新在前"按记录落库时间倒序（append-only 收尾写入时刻，近似完成时间）；"调用时间"以执行开始时间为准展示，两个字段详情均可见
- 节点级错误信息落库恒空为前序篇既有形态（节点步骤不记录错误文本）：错误定位 = 运行级错误文案 + 失败节点字段（前端据此高亮轨迹表中对应行）
- 输入/输出大文本已在落库边界按 16KB 截断并带截断标记——运行详情展示的是截断保真文本，非全文
- 运行历史查询窗口受保留期清理任务约束（默认 365 天可配）；被清理记录不可查属正常态
- 「运行历史」以新增区块形式融入详情页单列卡片流（具体组件形态在规划阶段定，不改既有区块结构）
- 下游消费者为前端自身；暂无其他模块消费本篇查询接口
- 明确不做（边界）：运行中实时进度查询（无进行中态）、按父运行反查子运行列表、列表筛选 / 搜索 / 时间范围过滤 / 统计聚合、对运行的重试 / 取消 / 删除操作、跨工作流的全局运行历史页、执行引擎与落库行为改动、按用户隔离
